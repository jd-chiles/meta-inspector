# Server video frame verification

Live mapping requires a local FFmpeg executable on the Node.js server. Use the maintained FFmpeg 9.0.2 runtime built from the signed upstream source release with `scripts/install-ffmpeg-runtime.sh`, then set server-only `FFMPEG_PATH` to the printed absolute path. Building requires `curl`, `gpg`, `tar`, `make`, GCC, and NASM; the script verifies the release signature against FFmpeg's pinned release-key fingerprint. The smaller build includes only the MOV/MP4 demuxer, H.264/HEVC/MPEG-4 decoders, selected-frame filters, and MJPEG output needed by this route. The older system `ffmpeg` can remain a fallback for local fixture checks; no FFmpeg call is made from the browser, and the server never fetches a client-provided URL.

During the original segment request, the server decodes the uploaded clip's validated SAM candidate frames and one context frame per second. A valid SAM result with no detections needs no stills and completes without a Muse call. The clip's computed SHA-256 must match its expected value before decoding. FFmpeg runs without a shell, with one decoder thread, a 9-megapixel input-frame ceiling (enough for 4096×2160 4K), at most 42 selected frames, a 45-second timeout, and JPEG output scaled to at most 1000×1000 pixels (1 megapixel). Temporary input and output files are removed after decoding. If FFmpeg is unavailable or cannot verify the frame timestamps, processing fails closed before Muse is called.

Only the derived JPEG stills remain in memory while the one-time map token is pending: at most 16 MiB for one walkthrough and 64 MiB across the server process. They expire with the 15-minute map token and are released when the user cancels, mapping completes, or the lease expires. The map request carries the identity and token only; client-submitted still images are rejected.
