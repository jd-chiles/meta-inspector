# Design — Move-in Ready video capture, draft review, and sign-off

## Product surface

The mobile primary navigation follows the supplied reference with Home, Review, Sign-Off, and Profile visible in a safe-area bottom bar. The app opens on Inspection Home: a next-step hero driven by the deterministic guide model, stage progress, all 11 Form 1083 requirements with per-requirement status, and room-evidence shortcuts. Capture is reached from Home (Continue or a room shortcut) and from contextual back actions in Profile and Review. Review presents the requirements as an ordered checklist with a progress bar and a continue-to-next-undecided action; selecting a requirement opens its focused detail where an unreviewed AI draft can pre-fill editable fields (choice, rationale, evidence, deficiency plan) while the save remains the explicit evaluator action that records the in-person acknowledgment. Requirements without an AI draft open with the spoken in-person answers quoted into the observation field, so nothing the evaluator already answered is re-typed. Its phone layout is camera-first: show one selected room and its saved-clip count, with other rooms behind a closed “Change room” picker. Keep the preview and record/upload actions together, then show the current filming prompt and two nearby steps as compact rows; the full checklist stays behind “View all prompts.” A filming prompt is complete only when tapped for the current room while recording and that take is then saved locally, or when tapped while a saved clip for that same room is present. An unsaved recording and a clip from another room or session never complete the prompt. Saved-clip evidence and provider details remain in expandable sections, and live mode is not shown as persistent mobile chrome. Review in the bottom bar is the visible transition from Capture to Draft Review; Capture has no second fixed action bar.

On phones, Capture, Draft Review, and Sign-Off & Export are separate screens, never a stacked long page. The shell fits the viewport, the main pane is the only scrolling region, and the bottom area shows either the three tabs or focused review actions. At 360×640 and 390×844 CSS-pixel viewports, measure the gap from the last visible Capture prompt/action to the top of the safe-area bottom navigation: it is at most 32 CSS px when content fits; if content exceeds the available pane, only the main pane scrolls and no actionable control is obscured. Document scroll width must not exceed viewport width at either size. The empty camera state is deliberate and never shows sample footage.

Review opens with four compact Form 1083 rows and a “View all 11 elements” action; selecting an element opens its focused detail with the unreviewed AI proposal, confidence, actual timestamped still, and separate worker choice. Through 959px, review keeps overview and assessment in separate focused states. At 960px and wider, desktop uses the same three navigation items in a sticky bar above the workspace, a side-by-side room video/prompt layout, and a split review list with one selected assessment. Sign-Off derives Approved / Not Approved / Needs human review only from evaluator decisions. Profile and setup controls remain accessible and do not displace the primary three-step flow.

The visual direction uses the reference's white/light-gray surfaces, dark text, blue actions, restrained green/red result badges, room/video hero, and thumb-reachable safe-area bottom bar. On desktop the same steps use a centered workspace and two-column evidence/review layout.

## Guided journey and voice delivery

Filming always precedes questions: each room is filmed first (shot guidance visible on screen), then its in-person checks are asked. Any room can be skipped from its filming card for units that lack it; skipping removes the room, its pending checks, and any running analysis for it. Bathrooms never ask for a smoke detector (faucet, toilet, fan only); bedroom and hallway detector checks remain. The AI Guide opens on phones as a collapsed one-line banner showing the current step title — never a half-screen card — and expands on tap; while recording, the banner captions the current filming cue so muted users keep guidance. The guided tour shows each room's shot list as a visible checklist with the spoken cue highlighted, and speaks only a short intro pointing at it. Spoken scripts stay short; nothing blocks filming on narration.

Home has one entrance: a single Start/Continue button opens the guided tour, which derives its position from saved data and ends at sign-off. The AI Guide offers no pre-start actions — before the flow has evidence it only points at Start — and tour film nodes link to the full capture screen so manual capture stays reachable inside the flow. A fresh Home leads with the voice-agent entry so launch is voice-first; one tap starts the tour and the spoken welcome follows immediately. Capture is a dashboard: the camera viewport with record actions pins to the top while prompts, checks, and analysis scroll beneath; the live filming cue captions on the viewport, and saving a clip brings the yes/no checks into view. Boot shows an inline splash card (brand, spinner, staged status with elapsed seconds) that paints before scripts parse and is removed when the app or unlock page renders, so a cold container boot reads as "waking the server" instead of a frozen screen; shell cache bumped to v5: navigations serve the cached shell instantly with background refresh, so repeat visits paint immediately even on a cold container.

Review keeps the human verdict per requirement with minimum typing: beside each current AI draft, a one-tap Confirm applies the suggestion as the evaluator's decision, where the tap itself is the structured in-person acknowledgment and plan review (the button names the verdict). In the guided tour the same confirm runs from a spoken yes through the review voice prompt — same evaluator identity, same completion timestamp, same detail-form fallbacks — and a spoken no opens the detail form for a differing verdict; needs-human-check stays an explicit tap. A Deficient draft without a complete suggested correction plan, without still evidence, or with an empty observation cannot one-tap confirm — it opens the detail form with guidance instead. Fire Safety confirms 11a and 11b together from the suggestion; split outcomes stay in the detail form. A successful confirm advances to the next undecided requirement. Nothing about the draft alone checks the acknowledgment or saves: without the human tap or spoken yes, no decision exists (REQ-005, REQ-009 unchanged).

Voice is static-first with one voice everywhere. The fixed script (tour intros, setup questions, room checks, filming cues, static assistant speeches, reprompts — 40 clips) is pre-generated once per voice/model into content-addressed public/voice/<text-hash>.mp3 files plus a manifest; the client plays the clip for exact text instantly, including on poor connections. Assistant guidance and filming cues use the same Fish pipeline as the tour — never the device voice directly — so the user hears one consistent voice. Dynamic prompts (room position, review excerpts) synthesize live and are cached server-side (bounded 16 MiB, immutable) so repeats are instant. Any missing clip or voice failure falls back through live speech to the device voice, then silent text; every voice turn keeps a tap equivalent. The tour opens with a Start tap (browser audio policy needs the gesture), then runs on spoken answers: setup questions, room checks, the evaluator name (spoken, read back, saved on yes), and per-draft yes/no confirms. Consent taps and the typed signature stay manual: consent is rare and high-stakes, and a signature cannot be spoken.

## Data model

One versioned local InspectionRecord owns intake, selected room, per-room media identity, extracted stills, the 11 model proposals, worker decisions, corrections/dates, and signatures. Fire Safety stores separate 11a unit-detector and 11b public/common-area detector outcomes. Each may be A, D, or needs-human-check; aggregate Fire Safety is D if either is D, A only if both are A, and otherwise unresolved. A proposal and evaluator decision are separate fields and have separate timestamps/revisions. Every A/D decision stores an inPersonCheckAcknowledgment containing evaluator name and completion timestamp; validation requires the name to match the decision and the check to be completed by decision time. Unreviewed and needs-human-check decisions do not carry this acknowledgment. The schema migration resets older A/D decisions without a valid acknowledgment to unreviewed and clears dependent sign-off, while retaining clip identities and model proposals.

Evidence identity is (sessionId, roomId, elementId, clipId, clipHash, stillId, frameIndex, timestampMs, schemaVersion, catalogVersion, analysisAttempt, revision). Schema version and catalog version are separate dimensions, never a combined or interchangeable version. Each clip, segmentation response, suggestion, and evaluator decision is bound to this identity. Before applying any async response or attaching evidence, match schemaVersion and catalogVersion independently and exactly against both the request identity and the current session/evidence identity, alongside every other applicable identity field. Missing or mismatched versions fail closed: discard the stale response, do not attach evidence, do not update decisions, and never restore a deleted session. Changing either version during migration/reset/catalog replacement invalidates outstanding analysis and affected prior suggestions/decisions/sign-off; renewed analysis and human review are required. Preserved historical clips are not silently rebound to a new identity. Changing or removing a clip invalidates suggestions and human decisions for affected elements; cancellation or deletion invalidates outstanding work. The local database holds blobs; React state holds serializable metadata and object URLs are transient.

The deriveInspectionResult function has no provider/model input. It reads only evaluator decisions and correction requirements. A model D without an actual still/time parses as needs-human-check; it cannot be exported as a worker deficiency. Any unresolved human decision blocks completed sign-off. HUD funding exits to the HQS notice state.

## Video and inference path

1. Capture or upload MP4/MOV; validate actual local media bytes, container, size, duration, tracks, and session/room identity.
2. Packet-copy remux supported MOV to MP4 without re-encoding; preserve the prior clip on failure; store media locally in versioned IndexedDB.
3. Extract supplementary actual stills locally for manual review.
4. Send the selected validated MP4 once to the same-origin stage=segment route. Validate actual server-received bytes and fixed server-owned room prompts.
5. Upload temporarily to the fixed Meta Files endpoint, run SAM per concept, and parse Responses SSE.
6. Decode candidate frames and 1-fps source-context stills (at most 30) from the hash-verified upload using server FFmpeg. Keep bounded server-derived JPEGs in an expiring one-time process-local mapping lease.
7. Send stage=map identity and signed token only; reject client-supplied media/stills. Map leased stills with Muse; optional Baseten Muse fallback is permitted only for eligible retryable Meta Muse provider failures.
8. Strictly validate the response and return sanitized bounded evidence for draft review. Persist only local evidence and separate evaluator decisions/sign-off. Generate local PDFs and HMIS-ready JSON under human review/sign-off rules.

The server uses @meta-sam/parser for SAM's Responses SSE grammar. Client-side video uses @meta-sam/video (Mediabunny/WebCodecs) to seek to packet-exact frames and extract supplementary stills for manual local review; native HTML video/canvas remains a browser fallback. These browser stills are not submitted in the map request. During the original segment request, the server verifies the uploaded clip hash and uses FFmpeg to decode authoritative candidate and context JPEGs from those exact bytes. The one-time map response returns bounded candidate JPEG bytes, dimensions, SHA-256, and frame identity for the exact stills Muse received. The client verifies each returned JPEG hash and full candidate identity against the segment response, then persists and displays those same bytes as model-cited evidence. A byte or identity mismatch removes that citation and forces needs-human-check. Responses are no-store and capped at 12 MiB; context stills are not returned. No still is generated or enhanced.

Meta's current Files API documents video/mp4 as its video MIME. The hosted media path accepts MP4 only. Supported QuickTime MOV clips are normalized locally with a size-bounded packet-copy remux through Mediabunny/WebCodecs; encoded video and audio are copied without re-encoding. Conversion must preserve required tracks and duration and remain under the output limit. Conversion failure keeps the previous clip intact and blocks live analysis. Other unsupported containers/codecs remain local-only; no full-frame-rate transcode is performed.

SAM prompts are server-owned, one concept per request, tied to the selected room. The browser sends the selected video once for stage=segment. After SAM returns, the server computes SHA-256 over uploaded bytes, verifies it against the expected video hash, matches candidate frame indexes to the validated video timeline, and decodes candidate JPEGs plus actual context frames sampled at 1 fps (at most 30) with FFmpeg. It stores bounded JPEG bytes in an in-memory, one-time mapping lease with full video identity and signed candidate token. The follow-on stage=map request carries identity and token only; it is rejected if it includes additional image/video fields and never uploads a second phone clip. The lease is capped at 16 MiB per operation and 64 MiB per server process and expires with the 15-minute token; mapping completion, cancellation, and expiry release it. Deployments must keep both stages on the same Node process while the lease is live.

Muse Spark receives leased candidate/context frames, catalog IDs/labels, and bounded room context. Meta Muse is primary. On a retryable Meta Muse provider failure only, an optional server-configured Baseten Muse Spark Open fallback may receive the same leased stills/context; it does not process video or replace SAM. Validation/setup/schema/safety failures do not trigger fallback. The UI discloses the optional provider and data transfer and only reports which provider returned a validated response. Every response is strictly validated against the allowlisted 11 IDs and actual frame/still references. No provider response body, key, or file ID reaches the client or logs. The app labels live upload as temporary provider processing with automatic expiry; local deletion does not claim to erase a provider copy.

Live server-side frame verification uses the maintained FFmpeg 9.0.2 runtime, built from signed upstream source with only supported MP4/MOV decoder and selected-frame JPEG features enabled. Install it with scripts/install-ffmpeg-runtime.sh and point server-only FFMPEG_PATH to the generated executable. If FFmpeg is unavailable or cannot verify selected frame timestamps, the request fails closed before Muse mapping. Temporary input/output files are removed after decode; only bounded JPEG bytes remain in the expiring process-local lease. FFmpeg is not shipped to the phone.

## Local PDF and JSON generation

Use pdf-lib to generate three separate self-contained local PDFs. Client-file export contains evaluator decisions and relevant stills; landlord export contains only evaluator-confirmed D items. The HMIS-ready PDF starts with the unchanged official LAHSA FY 2022–23 Form 1083, fills supported fields, flattens the form, and appends local evidence/continuation pages; a sibling JSON carries the local record. Export section 11a and 11b independently from corresponding evaluator outcomes, for 12 printed A/D marks across 11 logical areas. Planned reinspection dates appear in notes; the official completed-reinspection date remains blank until completion is recorded. The staged/mock-only export leaves participant/HMIS identity and unit address blank and is not case-ready. It is not an HMIS submission and provider acceptance is unverified. Each page carries a local/manual-upload notice. Pending, failed, rejected, and needs-human-check model proposals do not appear as approved findings. There is no direct HMIS route.

## Versioning and compatibility

This scope change advances the local inspection schema and catalog. Old image-only sessions remain in their prior store and are not silently reinterpreted as video evidence or moved into the new sign-off flow. Migration is explicit, recoverable, and preserves an export path for prior records. Local clear removes all current product-owned local records and clips; it cannot revoke prior provider calls or downloaded files.

## Verification focus

Test the exact three-step experience at 360px and desktop; the 360×640/390×844 Capture fit, HUD gate, recording replacement/deletion identity, duration/byte/container bounds, MOV packet-copy remux and failure preservation, actual extracted frame timestamp identity, server-side source hash/frame decode and 1-fps sample validation, map requests with identity/token only, rejection of client-supplied stills/video, one-time lease release/expiry/capacity behavior, strict SAM/Muse output, fallback only on eligible Meta Muse provider errors, no-evidence-to-D downgrade, race/cancel behavior, human-only result derivation, signed completion gate, landlord D-only export, JSON/PDF parity, escaping, offline persistence, and non-leakage of provider secrets/file IDs. Include independent schemaVersion-only and catalogVersion-only mismatches and missing-version responses, plus invalidation after either version changes; no stale attachment/decision/sign-off or deleted-session restoration is allowed. A real 30-second staged clip is required before claiming the SAM-to-Form mapping gate passed.

## Sprint additions (REQ-S/V/F/E/L/R/O)

Sprint 0 batch pipeline (REQ-S2/S5): `runRoomBatch` in `src/features/walkthrough/batch-scheduler.ts` is the single batch pool (max 2 rooms, `MAX_CONCURRENT_BATCH_ROOMS`; REQ-L2 reuses it for the offline queue runner). Rooms are pulled from a deduped FIFO (`createRoomBatchQueue`) shared with analyze-on-save, so rooms saved mid-run join the run. Each room runs the same guarded `analyzeRoomFor(roomId)` pipeline with per-room generation, abort controller, and cancel tracker; batch pipelines bind the full (session, room, video, attempt, schema, catalog) identity but not the UI selection (`requireSelectedRoom: false`), while manual runs keep the strict check. The analyze-on-save gate is the pure `shouldAutoEnqueueOnSave` predicate (tour + batch consent, LAHSA funding, live mode, online, deduped, skipped while a manual run is in flight, while unresolved failures await review, and for MOV). Cancel and navigation-away abort every in-flight room; each room proves by a persisted proposal bound to its current clip. Server: session operations isolate by full request-identity digest, cap 2 per session. Analysis uses only the first 30 s of a clip (`ANALYSIS_CLIP_CAP_SECONDS`); the map payload carries the earliest 12 sample stills within 4 MB.

Sprint 1 voice and sign-off (REQ-V1/F1/F2). ASR routing: `handleTranscribeRequest` validates the mic clip once (existing `MAX_TRANSCRIBE_BYTES`/sniff rules), then routes by `VOICE_ASR_PROVIDER` (default "muse"). The Muse path (`src/server/voice/muse-transcribe.ts`) converts to WAV with server FFmpeg and POSTs the Meta cookbook wire format with a 20 s timeout. Any Muse error falls back to Fish `transcribeAudio` exactly once; the JSON response always carries `providerUsed` ("muse"|"fish") and the voice prompt surfaces the backup engine. Unknown provider values fail closed (503, no provider called). Dual sign-off: `MoveInReadyInspection` carries `signoff` and `participantSignoff` independently; all existing signoff invalidations clear both, while participant revoke clears only the participant side. Completion of rooms/decisions (`deriveFinalInspectionResult`) is unchanged; the participant signature is an additional export gate enforced in `buildExportFile`, export `assertExportable`, and the export-button disabled state. Exports embed a participant block mirroring the evaluator block (JSON) and both signatures plus both attestation texts (all PDFs). Record-aware checks: `VOICE_ROOM_CHECKS` and `MOVE_IN_READY_ELEMENT_CRITERIA` stay the constant base; `checksForRoom(record, roomId)` and `checklistItemsForElement(record, elementId)` append the strobe question / Fire Safety criterion only when `participantVisualAlarmsRequired` is true. All four room-check derivations (tour engine, tour view, capture section, voice-turn advance) and the review criteria panel use the helpers.

Sprint 2 workflow outputs (REQ-E1/E2/E3). LAHSA JSON (`src/export/lahsa-1083.ts`): pure builder over `{sessionId, fundingType, decisions, signoff, participantSignoff, participantVisualAlarmsRequired?, inspectionLocation?, generatedAt?}`. Element map: nine elements to their like-named criteria, Access to `fire_safety.emergency_exit`, Fire safety 11a/11b to the detector subfields, aggregate Fire safety to `additional_standards`. Determination is derived from the emitted criteria object by `deriveLahsaDetermination` ("APPROVED" only when every criterion is true, else "NOT APPROVED"; null `visual_alarms_approved` never blocks) and re-derived as an internal assertion before return, making an inconsistent export impossible. Recorded GPS arrives as `property_address.geolocation` (null when uncaptured). Case note (`src/export/case-note.ts` + `src/server/exports/polish-case-note.ts`): the template builder delegates gating and determination to `buildLahsa1083Json`, so the note can never disagree with the LAHSA JSON. Polish is a same-origin route returning `{text, polished[, model]}`; the client (`requestCaseNotePolish`, 35 s timeout) treats every failure as "use the template". The route validates input (JSON, single `text` key, ≤16_384 chars), honors the Meta base-URL allowlist, and keeps keys and provider bodies server-side. Bilingual fix list: `FIX_LIST_STRINGS` holds the complete boilerplate per language; `buildMoveInReadyPdf(input, kind, language = "en")` applies it to `landlord-fix-list` only. ES filenames gain an `-es` suffix. Recorded text flows through the existing `cleanText`/`cleanPdf` path unchanged.

Sprint 3 lifecycle (REQ-L1/L2/L3). Re-inspection: `PriorDeficiencySnapshot` lives only on `unreviewed` decisions; saving a new A/D decision replaces the decision and drops the snapshot, which releases the `guidedReviewQueue` re-inspection filter element by element; saving while still unreviewed preserves the snapshot (`unreviewedDecisionPreservingSnapshot`). `startReinspectionDecisions` is pure (decision set in/out + count); sign-off resets stay at the record layer (both sign-offs). Before stills are snapshot stillIds resolved best-effort against on-device evidence views at render time. Offline queue: `analysisQueue` is the persisted source of truth for rooms needing analysis; all mutations go through `enqueue/dequeue/pruneAnalysisQueue`; the runner is a trigger only — scheduling, identity guards, cancel, and progress remain owned by the batch driver (Sprint 0 contract). The runner mirrors REQ-S5's failure guard: a finished failed batch never auto-restarts; retry stays manual. GPS attestation: `InspectionLocation` is write-on-tap, rounded at construction via `buildInspectionLocation`, validated by `validateInspectionLocation`, and is not an input to finalization, sign-off, or any export gate.

Sprint 4 reach (REQ-R1…R4). Pre-screen is illustrative-first: the Home card answers only the literal demo address from a labeled example. REQ-R1 live path (verified 2026-11-03): any other address runs `POST /api/prescreen` — one Census geocode fanning out to LADBS open cases, LAHD violations, FEMA NFHL flood, HUD lead index, and OpenFEMA disasters, all keyless with per-source degradation. No building data is persisted, queries are logged nowhere and untraced, and owner/APN + SAM + EPA proximity stay deferred until their sources verify. The guided tour is bilingual in narration only. `tourLanguage` on the inspection record selects English or Spanish tour scripts, setup questions, filming cues, room checks, reprompts, and review/finish narration; check sequencing, review detail, sign-off, exports, and the Form 1083 catalog stay English. Spanish speech uses the separate server-only `FISH_VOICE_ID_ES` owner voice for live TTS and for `public/voice/es/` pre-generated clips; without it the ES toggle is disabled and ES speak requests fail closed. Voice answers parse in both languages through the shared deterministic parser. The detector test is evidence-only: a live-preview still captured beside (never instead of) the human's detector yes/no answer, stored on the room's current clip under a `detector-test-` still id with a free still-timeline slot, and surfaced in the Fire Safety evidence picker as a live capture. Skip records nothing; failures return messages and never block the tour. Accuracy claims stay gated: the app carries the demo-checklist mapping notice plus a pointer to the demo-notes miss list, and the scorecard shell in `docs/DEMO.md` holds blank fields until the recorded live protocol run fills them.

Sprint 5 observability (REQ-O1/O2). `src/server/observability/langfuse-trace.ts` is the single server-only tracing seam: configured only when both `LANGFUSE_SECRET_KEY` and `LANGFUSE_PUBLIC_KEY` are set (otherwise a zero-overhead no-op), one trace per analysis attempt shared by the segment and map stages via the deterministic `analysisTraceId`, nested spans per pipeline phase (`preflight-decode`, `sam-upload`, `sam-concept:*`, `select-candidates`, `frame-decode`, `validate-proposals`) plus a `muse-map` generation observation, and one best-effort flush per request. `runSpan`/`runSpanSync` fail spans with safe codes and rethrow so tracing never masks pipeline errors. Payloads are metadata only (identities, hashes, labels, boxes, confidences, timestamps, counts, prompt SHA-256, Muse response text, proposal summaries); media bytes, pseudonyms, names, keys, and provider bodies are structurally excluded. The eval dataset (`src/server/observability/eval-cases.ts`, `meta-inspect-walkthrough-v1`) pins five accuracy dimensions as validated reference-only cases; the owner pushes them with `scripts/langfuse-eval-push.mjs` and scores runs in Langfuse.
